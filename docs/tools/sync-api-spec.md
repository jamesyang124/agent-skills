# Sync API Spec Skill

A skill that scans all API routes in the project and maintains `docs/agents/api-spec.md` — a machine-readable API reference for coding agents, frontend, and product to understand what the project's APIs do.

## Supported Frameworks

| Language | Frameworks | Source |
|----------|-----------|--------|
| Go | Gin, Echo, Chi | Swaggo annotations + handler code |
| Ruby | Rails | rswag, apipie, or inferred from controllers |
| Node.js | Express, Fastify, Koa | JSDoc `@swagger`, tsoa, or inline code |
| Python | FastAPI | Decorators + Pydantic models |
| Python | Flask | flasgger, flask-restx, or inferred |
| Any | — | Direct `swagger.json` / `openapi.yaml` |

## Features

### Incremental Scanning
- Parses existing `docs/agents/api-spec.md` to find already-documented routes
- Scans the router for all current routes
- Re-scans handlers **only for new or user-named routes** — existing entries are preserved
- Flags routes removed from the router (asks before deleting entries)

### Local-First Output
- Primary output is `docs/agents/api-spec.md` in the consuming project
- Compact, structured format designed for agents, FE devs, and product to read
- Optional Confluence publish step offered after local file is written

## Usage

```
# Full sync (all routes)
sync api spec

# Specific routes only
sync api spec for /api/v1/auth/login

# Using an OpenAPI spec file
sync api spec using swagger.json
```

## How It Works

1. Read `project-config.md` for framework, router path, handler/DTO directories
2. Scan the router file using framework-appropriate patterns
3. Diff against existing `docs/agents/api-spec.md` (if present)
4. Scan handlers only for new (or user-named) routes
5. Write updated `docs/agents/api-spec.md`
6. Offer optional Confluence publish

## Output Format

See `references/api-spec-format.md` for the full format spec. Summary:

```markdown
# API Spec — {Project Name}
> Generated by sync-api-spec. Last updated: {date}

## Endpoints Summary
| Method | Path | Purpose |
|--------|------|---------|

---

## POST /api/v1/auth/login
**Purpose**: Authenticate user, return session token.
**Auth**: none
**Request** / **Response** / **Example** ...
```

## Setup

Run `setup-project-config` before first use:

```
"set up project config"
```

This writes `.agent-settings/project-config.md` with framework, router path, handler/DTO directory, Confluence space, and other project details. All skills read from this file.

## Confluence (Optional)

Confluence publish is an optional post-step, not a requirement. The skill will ask after writing the local file. Requires the Atlassian MCP server to be configured if you choose yes.

## Tips

- Always provide the API path (e.g., `/api/example-service/v1/endpoint`)
- For updates, you can use either page ID or search keywords
- The skill automatically detects middleware and authentication requirements
- JSON response examples are generated from DTO structures
- Version numbers are automatically incremented in the Change Log
