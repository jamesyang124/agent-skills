# Config Output Format

## File: `.agent-settings/project-config.md`

`project-config.md` is a **namespaced per-MCP settings file**. Layout:

- `## MCP: <name>` — one section per installed MCP that has project-scoped, non-secret knobs. Connection
  URLs and credentials are **never** written here — they live in the global store `~/.env.mcp-<name>` (or
  OAuth) and are consumed by the MCP server.
- `## SDD Tool` — top-level (spec-kit / openspec are CLI tools, not MCPs).
- `## Code Structure` / `## Documentation Format` — auto-detected in Phase 1.

Only emit `## MCP: <name>` sections for MCPs that are actually installed (found in `.mcp.json` /
`.claude/mcp.json` / `.vscode/mcp.json`) and have at least one non-blank field.

### Resolution order (precedence)

For any value a consumer skill needs:

1. **`~/.env.mcp-<name>` dominates** — it is the authoritative source for connection URLs and all
   credentials. Consult it first.
2. **`project-config.md` is a per-project override** — a field here wins **only when explicitly present**
   for this repo. Blank or absent → the global env value stands.
3. **Secrets are env-only** — tokens, PATs, passwords, API keys are read from `~/.env.mcp-<name>` (or
   OAuth) and are **never** written to or overridable from `project-config.md`.

So `project-config.md` never *replaces* the env store; it layers non-secret, per-project overrides on top
of it (e.g. a Base URL override when this one repo targets a different instance).

Write the file using this format (sections present depend on installed MCPs):

```markdown
# Project Configuration
# Generated by setup-project-config skill. Re-run the skill to update.

## MCP: atlassian
# Connection (URL + creds) inherited from ~/.env.mcp-atlassian via the Atlassian MCP.
# Add "Base URL:" ONLY to override the global instance for this repo (rare). Omit otherwise.
- Confluence Space Key: ENG
- Jira Project Key: PROJ
- Jira Issue Type: Story

### Common Parent Pages
| Name | ID | URL |
|------|----|-----|
| Technical Design | 1234567890 | https://yourcompany.atlassian.net/wiki/spaces/ENG/pages/1234567890 |
| API Documentation | 2345678901 | https://yourcompany.atlassian.net/wiki/spaces/ENG/pages/2345678901 |

### Page Title Format
API Spec: {METHOD} {path}

## MCP: playwright
# No credentials — local browser automation.
- User-Agent: HTCVRSDET
- Allowed Domains: portal.your-org.com, docs.your-org.com
- Base URL: https://staging.example.com

## MCP: sentry
# Auth via OAuth (mcp.sentry.dev) or SENTRY_ACCESS_TOKEN — not stored here.
- Org Slug: my-org
- Project Slug: my-proj

## MCP: azure-devops
# Connection (org URL + PAT) inherited from ~/.env.mcp-azure-devops.
- Organization: my-org
- Project: my-project
- Default Repo: my-repo

## SDD Tool
- Tool: spec-kit
- Specify command: spec-kit specify
- Plan command: spec-kit plan

## Code Structure
- Language: Go
- Framework: Gin (github.com/gin-gonic/gin)
- Router file: router/router.go
- Handler directory: handler/
- DTO directory: dto/
- Service directory: service/
- API base path prefix: /api/v1/

## Documentation Format
- Style: Swaggo inline annotations
- Tags: @Summary, @Description, @Router, @Param, @Accept, @Produce, @Success, @Failure, @Security
- Binding: c.ShouldBindJSON(), c.ShouldBindQuery(), c.Param(), c.Query()
- Response: c.JSON(), c.String(), c.Status()
```

### Field notes

**`## MCP: atlassian` — Common Parent Pages table:**
- Construct the URL as `{Confluence base URL}/spaces/{Space Key}/pages/{ID}`, where `Confluence base URL`
  is the section's `Base URL` override if present, otherwise `CONFLUENCE_URL` from `~/.env.mcp-atlassian`
- If neither an override nor the env var is available, write the ID only and leave the URL cell blank
- If user provided a name but not an ID (or vice versa), omit that row

**`## MCP: <name>` sections generally:**
- Omit the whole section if the MCP is not installed or the user left every field blank
- Never write a token, password, PAT, or connection URL into any MCP section (Base URL override excepted)
- Keep field names in sync with the per-MCP registry in `SKILL.md` (Phase 2)

**Documentation Format:**
- Swaggo: list the annotation tags detected in handler files
- Node/JSDoc: list the JSDoc tags found
- FastAPI: note that docs are auto-generated from function signatures
- If not detected, write: `Style: not detected`

**SDD Tool:**
- Detect by scanning for `.speckit`, `spec-kit.json`, `openspec.json`, or `.openspec` in project root
- If detected: write the matching tool name and its commands
- If not detected: default to `spec-kit` and standard commands
- Valid values: `spec-kit`, `openspec`

## Notes

- Write the file to `.agent-settings/project-config.md` (relative to the project root)
- Do not commit this file — it is gitignored in the skills template repo
- If the user is running this inside their project repo (not the template repo), they can choose to commit it there
- After writing, tell the user which skills will now use this config, and which section each reads:

  | Consumer skill | Section(s) read |
  |----------------|-----------------|
  | `sync-api-spec` | `## MCP: atlassian` (space / parent pages), Code Structure, Documentation Format |
  | `ado-open-pr` | SDD Tool |
  | `tech-plan-to-wiki` | SDD Tool |
  | `sdd-qa-to-ticket` | SDD Tool |
  | `install-external-skills` | whole file (derives skill recommendations) |

  > Keep this table in sync with reality: it is the authoritative consumer list. When a skill starts or stops
  > reading `project-config.md`, update this row. Verify with:
  > `grep -rl "project-config" .agent-settings/skills --include=SKILL.md`
